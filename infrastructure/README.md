# AWS Infrastructure

Terraform provisions the production boundary for the VisualKit Go API and
asynchronous worker:

```text
Internet
  -> public ALB
  -> private ECS/Fargate API service

private ECS/Fargate worker service
  <- private SQS jobs queue

API and worker
  -> private RDS PostgreSQL
  -> private S3 assets bucket
```

The API and worker are separate ECS services, but the current worker binary
dispatches both `image_analysis` and `image_generation` jobs. They can be split
into separate task definitions later without changing the API or SQS contract.

## Provisioned resources

- VPC with public subnets for the ALB and private subnets for ECS/RDS.
- NAT gateways for private-task egress to AWS and provider endpoints.
- ECS cluster with separate API and worker task definitions/services.
- Public Application Load Balancer with HTTP-to-HTTPS redirect.
- HTTPS listener and `/ready` target health check.
- Private RDS PostgreSQL instance.
- Private, versioned, encrypted S3 bucket with public access blocked.
- SQS jobs queue and dead-letter queue with long polling and redrive policy.
- Scoped ECS task IAM roles for S3 and SQS.
- Secrets Manager database secret and optional provider-key secret references.
- ECR repositories with scan-on-push and lifecycle retention.
- CloudWatch log groups and queue/HTTP autoscaling.

Resources are named with `project_name` and `environment`, so development,
staging, and production do not share queues, buckets, databases, or services.

## Prerequisites

- Terraform `>= 1.6`.
- AWS CLI configured for the target account.
- Docker.
- An ACM certificate in the same AWS region as the ALB.
- A DNS record for `api_domain_name` pointing to the ALB output.
- A remote Terraform state S3 bucket and DynamoDB lock table.

The state bucket and lock table are intentionally not created by this stack.
Create them in a separate bootstrap account or approved platform module, then
copy `terraform/backend.hcl.example` to an environment-specific file and set
real values. Do not commit that file.

```bash
cp infrastructure/terraform/backend.hcl.example \
  infrastructure/terraform/backend-staging.hcl
# Edit the bucket, key, region, and DynamoDB table.
```

## Environment configuration

Copy one environment example and keep the real file out of source control:

```bash
cp infrastructure/terraform/staging.tfvars.example \
  infrastructure/terraform/staging.tfvars
```

Set at least `aws_region`, `availability_zones`, `certificate_arn`, and
`api_domain_name`, together with the intended database sizing and deletion
protection settings.

Provider API keys and authentication credentials do not belong in tfvars. Store
them in Secrets Manager and pass their ARNs through
`image_generation_api_key_secret_arn`, `internal_job_token_secret_arn`, and
`db_secret_kms_key_arn` when applicable. API and worker ECS execution roles are
separate; add customer-managed KMS key ARNs for their injected secrets through
`api_secrets_kms_key_arns` and `worker_secrets_kms_key_arns`.

The RDS password is generated by Terraform and written to the
environment-specific database secret. Protect the remote Terraform state with
encryption, IAM, and locking because it contains infrastructure-managed secret
material.

## Authentication requirement

The production examples use `auth_mode = "bearer"`. The API's `AuthProvider`
interface is provider-neutral, but the current `cmd/api` entrypoint does not
select a concrete identity-provider verifier. Before enabling production
traffic, inject the chosen verifier through `httpapi.Dependencies.Auth` or add
an equivalent deployment-specific adapter.

Do not switch production to development authentication. Development mode
accepts `X-User-ID` and is only valid for local development/test environments.

## First deployment

Terraform task definitions reference immutable ECR image tags. Bootstrap the
repositories before creating ECS services:

```bash
cd infrastructure
export ENVIRONMENT=staging
export AWS_REGION=us-east-1
export AWS_ACCOUNT_ID=000000000000
export TFVARS_FILE="$PWD/terraform/staging.tfvars"
export BACKEND_CONFIG="$PWD/terraform/backend-staging.hcl"

terraform -chdir=terraform init \
  -backend-config="$BACKEND_CONFIG"
terraform -chdir=terraform apply \
  -target=aws_ecr_repository.api \
  -target=aws_ecr_repository.worker \
  -var-file="$TFVARS_FILE" \
  -var="aws_region=$AWS_REGION"
```

Build and push the API and worker images:

```bash
PROJECT_NAME=visualkit ./scripts/build-and-push.sh
# Export the API_IMAGE and WORKER_IMAGE values printed by the script.
```

Deploy:

```bash
export API_IMAGE=000000000000.dkr.ecr.us-east-1.amazonaws.com/visualkit-staging/api:TAG
export WORKER_IMAGE=000000000000.dkr.ecr.us-east-1.amazonaws.com/visualkit-staging/worker:TAG
./scripts/deploy.sh
```

Run migrations as a one-off Fargate task:

```bash
export ECS_CLUSTER=visualkit-staging
export SUBNETS=subnet-private-a,subnet-private-b
export SECURITY_GROUPS=sg-api
export TASK_DEFINITION=visualkit-staging-api
./scripts/migrate.sh
```

Run migrations before relying on `/ready` for application traffic.

## Updates and rollback

Build a new immutable image tag, then run `deploy.sh` with the new image URIs.
ECS deployment circuit breakers are enabled and automatically roll back a
failed service deployment.

For a manual rollback, provide the previously known-good ECS task-definition
revisions:

```bash
AWS_REGION=us-east-1 \
ECS_CLUSTER=visualkit-staging \
API_SERVICE=visualkit-staging-api \
WORKER_SERVICE=visualkit-staging-worker \
API_TASK_DEFINITION=visualkit-staging-api:12 \
WORKER_TASK_DEFINITION=visualkit-staging-worker:12 \
./scripts/rollback.sh
```

Never run `terraform destroy` against production as part of deployment or
rollback. Production RDS, ALB, and ECS deletion protection is enabled by the
production example.

## Validation

```bash
terraform -chdir=infrastructure/terraform fmt -recursive
terraform -chdir=infrastructure/terraform init \
  -backend-config="$BACKEND_CONFIG"
terraform -chdir=infrastructure/terraform validate

cd backend
GOCACHE=/tmp/visualkit-backend-cache go test ./...
GOCACHE=/tmp/visualkit-backend-cache go vet ./...
GOCACHE=/tmp/visualkit-backend-cache go build ./cmd/api ./cmd/worker ./cmd/migrate

docker build -f Dockerfile .
docker build -f Dockerfile.worker .
```

The repository does not execute AWS applies automatically. Review the plan and
approve changes in the intended environment.
